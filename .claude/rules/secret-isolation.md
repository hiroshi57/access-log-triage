# 秘密のコンテキスト隔離ルール

> **適用対象**: 全エージェント（Lead / Worker / Reviewer）
> **起源**: 提案 `harness-proposals/2026-09-25-context-leakage-secret-isolation.md`（提案 A・B・C・E）／根拠 arXiv:2608.19857
> **承認**: 2026-09-28 人間承認済み（提案 A〜E すべて、未解決論点 P-1〜P-4 は既定案で確定）

## 背景

モデルが秘密の開示を正しく拒否していても、コンテキストにある秘密は、無害な出力の統計的性質
（数値の選び方・長さ・書式）に乗って漏れうる。商用モデル8種の実験では、2桁の秘密がほぼ100%、
4桁が82%で完全一致復元された。さらに次の2点が示されている。

- **機密指示を強く書くほど漏れる**（守らせる値を避けようとする歪みそのものが手がかりになる）。
- **出力フィルタや LLM 審査では検出できない**（文章に秘密が出ていなくても漏れる）。

確実な防御は「コンテキストに入れない」ことだけである。

## 用語

| 種別 | 内容 | 出力フィルタで防げるか |
|---|---|---|
| **L1 明示漏洩** | 秘密が文章・思考・ログに平文で出る | 一部可 |
| **L2 受動漏洩** | 無害な出力の統計に秘密が乗る | 不可 |
| **L3 能動漏洩** | インジェクションで出力の特徴に符号化させる（例: 各桁を `!` の個数で表させる） | 不可 |

- **秘密**: 認証情報・API キー・トークン・アカウント ID・個人情報・クライアントの生データ。
- **第三者テキスト**: Web ページ・LP・広告レポート・顧客 CSV・社外からのメール本文。
  社内 Slack は含めない（P-2 確定）。

## ルール（MUST）

1. **秘密を表示しない。** 秘密を含むファイルを Read / cat / head / grep 等で表示しない。
   パスや存在の確認はよいが、中身を出すコマンドは実行しない。
2. **値はツール側で読む。** 値が必要な処理は、スクリプト・ツール・MCP サーバーの内部で読み込み、
   LLM には処理結果だけを返す（DI-MCP と同じ方式）。
3. **値を置いて「守れ」と書かない。** プロンプト・AGENTS.md・システムプロンプトに秘密の値を書いたうえで
   秘匿を指示しない。値が必要ならルール2の方式に置き換える。言い回しを弱めても安全にはならない。
4. **第三者テキストと秘密を同居させない。** Lead は、第三者テキストを読む作業と、秘密をコンテキストに持つ
   作業を、同じ Worker に割り当てない。両方必要なら、秘密側をツール側に寄せる。
5. **外部に出る成果物を作る Worker に秘密を持たせない。** クライアント送付物・メール・公開画面などが対象。
6. **記憶・ログに秘密を書かない。** `.claude/agent-memory/` と `.claude/harness-logs/` に秘密の値を書かない。
   検証コマンドの出力を生ログとして保存する前に、既知の秘密値を `***` にマスクする。
   このマスクは要約ではなく秘密の除去なので、`memory-curation.md` ルール4（生ログ逐語保存）の
   例外として扱う（P-3 確定）。マスクしたことは `retries.log` 等に1行残す。

## 例外（P-4 確定）

秘密そのものを扱う実装作業など、秘密がコンテキストに本質的に必要なタスクは、次の3条件をすべて
満たす場合に限りルール1を外れてよい。

- ローカル限定で作業する
- 秘密を含む出力を外部へ送信しない（PR 本文・コメント・送付物を含む）
- 秘密を含む出力を記憶・生ログに保存しない

## セルフチェック（コミット前）

- このタスクで秘密をコンテキストに入れる必要があったか。あったなら、ツール側に寄せられないか検討したか。
- 記憶・ログに秘密らしき文字列を書いていないか（下の grep、または `harness-retro.md` 提案6）。

```bash
grep -rEn '(sk-[A-Za-z0-9]{20,}|AKIA[0-9A-Z]{16}|-----BEGIN [A-Z ]*PRIVATE KEY-----|[A-Za-z0-9+/]{40,}={0,2})' \
  .claude/agent-memory .claude/harness-logs 2>/dev/null | head
```

- 検出しても**自動削除しない**（`memory-curation.md` ルール3）。人間に報告し、人間の指示で伏せ字化する。
  伏せ字化した場合は、何を伏せたかをコミットメッセージに残す。

## ツール層の安全網（提案 D・反映済み 2026-09-28）

本ルールはエージェントの遵守に依存する。事故防止の安全網として、各案件の `.claude/settings.json` に
秘密ファイルの Read を禁止する deny ルールを入れる（提案 D）。セキュリティ設定の変更にあたるため、
反映は人間の判断による。2026-09-28 に人間の明示指示で ai-platform-template と yosikei-agents に反映済み。他案件へ広げる場合も人間が判断する。対象パス（P-1 確定）: `config/secrets.yaml`・`.env`・`.env.*`・`*.pem`・
`*credentials*.json`。diff は提案書の提案 D を参照。
